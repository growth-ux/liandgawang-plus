# 粮小二｜找粮源——页面与 Agent 设计规格

> 日期：2026-08-22  
> 状态：已确认，按竞赛稳定演示范围调整  
> 范围：粮小二独立服务页、粮源市场、寻源方案、寻源任务、供应方、常驻对话 Agent、固定 Mock 数据与跨小二交接

---

## 1. 设计目标

粮小二不是一张聊天卡，也不是必须从瞻小二进入的下游步骤。它是一个可以独立使用的找粮工作台：用户即使没有明确采购任务，也能先浏览一批粮源；有采购条件后，再由粮小二完成筛选、比较、解释、任务沉淀和后续交接。

首版要跑通的代表场景是：

> 深圳采购人员需要 120 吨东北二等玉米，希望 7 天内具备发运条件。粮小二从固定演示粮源中筛出一条主推粮源、一条备选粮源，并明确说明低价粮源未入选的原因以及下一步必须核验的事实。

需要解决的真实痛点：

- 粮源信息分散，采购人员需要反复整理品种、等级、数量、价格口径和交收条件。
- 最低价不一定能满足质量、数量和发运时间，人工比较容易遗漏硬条件。
- 采购决策需要主推、备选、淘汰原因和核验清单，而不是一段泛化建议。
- AI 结论必须可追溯到候选粮源和规则，不能用自然语言掩盖数据缺失。

竞赛阶段的成功标准：

- 演示环境不依赖外部网站、网络稳定性或公开接口结构。
- 同一组条件始终得到可复现的主推、备选和淘汰原因。
- 用户能从无任务浏览自然进入任务态，也能从瞻小二携带需求进入。
- LangChain 对话与页面操作共享上下文，写操作必须确认。

## 2. 已确认的核心决策

### 2.1 数据策略：Mock-first

由于首版是 AI 竞赛项目，稳定演示优先，暂不接入任何公开数据源：

- 粮源、报价、数量、质检、发运窗口、供应方和履约信息全部使用本地固定 Mock 数据。
- Mock 数据随应用初始化写入本地 MySQL，使用固定业务主键和固定数据集版本，重复初始化不会产生重复记录。
- 所有 Mock 事实统一标记 `data_kind=simulated`，前端统一展示“演示数据”，不得使用“公开挂牌”“实时行情”“真实库存”等措辞。
- 用户输入继续标记 `data_kind=user_input`，规则或 AI 生成的判断标记 `data_kind=inference`。
- 市场概览在每次请求时从同一批 Mock 粮源聚合计算，但只代表演示数据集，不代表真实市场。
- 首版不做公开源解析、抓取、定时同步、手动刷新、快照切换、公开/演示模式切换和数据新鲜度判断。

页面常驻展示：

- `当前为演示数据`
- `演示数据集：liang-v1`
- `数据生成时间：2026-08-22 10:00`

这里的“数据生成时间”是固定 Mock 数据集的版本时间，不是外部来源更新时间。

### 2.2 核心输出

粮小二最终输出固定分为三部分：

1. **主推粮源**：当前条件下最值得优先核验的一条粮源。
2. **备选粮源**：主推不可用时可继续核验的一条替代粮源。
3. **待核验清单**：在任何联系、询价或交易动作前必须确认的事实。

同时保留：

- 未入选原因
- 候选对比
- 当前任务条件
- 下一步建议
- 交接运小二所需的结构化摘要

### 2.3 单粮源优先

首版只做单粮源满足需求的主推与备选，不做多粮源拼单。若没有任何单粮源满足数量、等级或发运要求，系统返回无结果和放宽建议，不自动组合多个来源。

### 2.4 Agent 框架

所有 Agent 相关能力统一使用 LangChain：

- LangChain 负责意图理解、只读工具选择、上下文组织和结果解释。
- 硬条件过滤、排序、候选选择和状态写入使用普通 Python 服务。
- 不允许模型直接修改数据库或自行触发交接。
- 任何创建任务、保存方案、加入候选和交接动作均需要用户确认。

## 3. 产品原则

### 3.1 粮小二可以独立成立

`/agent/liang` 是一级产品入口。没有瞻小二任务时，默认展示完整演示粮源市场；从瞻小二进入时，只是自动带入采购条件和来源上下文。

### 3.2 交易列表是默认主体

默认入口是一批高密度粮源列表，形态接近粮食交易页面，而不是大面积聊天欢迎页。对话栏常驻，但不抢占列表主体。

### 3.3 没有条件时不伪造个性化推荐

无采购任务时只展示：

- 演示市场概览
- 全部演示粮源
- 基于数据集的市场发现
- 引导用户描述找粮需求的粮小二对话

不得展示“为你推荐”“匹配率”等个性化表达。

### 3.4 先硬过滤，再比较

品种、数量、等级、年份、价格上限和最晚发运时间属于硬条件。任何候选只要明确不满足硬条件，就不能因为价格低或供应方表现好而成为主推。

### 3.5 不制造虚假的精确度

- 不计算未定义口径的综合评分。
- 不比较不同价格口径下的绝对差价。
- 不把挂牌数量写成已锁定库存。
- 不把 Mock 质检、库存和履约写成真实事实。
- AI 推断必须展示支撑粮源和使用的规则。

### 3.6 控制首版职责

粮小二首版负责找粮、比较、核验和交接，不负责自动联系供应方、自动询价、下单、签约、付款或到厂成本精算。

## 4. 页面信息架构

页内 Tab 可按产品目标重新组织，首版采用四个：

1. **粮源市场**：默认入口，浏览、搜索、筛选和加入候选。
2. **寻源方案**：查看主推、备选、淘汰原因和待核验项。
3. **寻源任务**：管理独立创建或从瞻小二承接的任务。
4. **供应方**：查看演示供应方档案、关联粮源和核验状态。

全局布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 粮小二 / 当前任务 / 演示数据标识 / 对话入口                  │
├──────────────────────────────────────────────────────────────┤
│ 粮源市场  寻源方案  寻源任务  供应方                        │
├────────────────────────────────────────────┬─────────────────┤
│ 当前 Tab 主内容                            │ 粮小二对话抽屉  │
│                                            │ 可收起、跨 Tab  │
│                                            │ 保留上下文      │
└────────────────────────────────────────────┴─────────────────┘
```

## 5. 双入口与页面状态

### 5.1 独立进入

用户直接打开 `/agent/liang` 时：

- 当前 Tab 为“粮源市场”。
- 展示完整 Mock 粮源列表和演示市场概览。
- 不自动创建寻源任务。
- 不自动生成主推和备选。
- 对话栏提示“告诉粮小二你要找什么粮”。

用户可通过两种方式进入任务态：

- 在对话栏描述需求，粮小二提取条件并展示确认卡。
- 点击“新建寻源任务”，在结构化表单中填写条件。

### 5.2 从瞻小二或我的办事进入

若 URL 带 `task_id` 或由交接记录进入：

- 顶部显示当前采购需求摘要和来源。
- 自动将任务条件映射到筛选器。
- 粮源市场仍是默认 Tab，用户先看到匹配范围。
- 已有运行结果时显示主推草案和备选草案摘要。
- 对话栏读取同一任务上下文。

瞻小二交接只提供任务上下文，不是粮小二运行的前置依赖。

### 5.3 从无任务切换到任务态

创建任务前必须展示确认卡，包括品种、数量、等级、年份、目标地区、最高价格和最晚发运时间。用户确认后才：

- 创建 `sourcing_task`
- 执行一次确定性寻源
- 保存 `sourcing_run` 与候选结果
- 切换到任务态

### 5.4 退出任务

“退出当前任务”只清除页面上下文并恢复完整粮源市场，不删除任务数据。

## 6. 共通页面框架

### 6.1 页面头部

页面头部包含：

- 粮小二图标、名称和一句话职责
- 当前任务摘要或“尚未创建寻源任务”
- 常驻琥珀色标签：`当前为演示数据`
- 演示数据集版本和生成时间
- 粮小二对话展开/收起按钮

不提供“刷新外部数据”按钮。页面重新请求 API 只刷新当前视图，不改变 Mock 数据集。

### 6.2 常驻对话栏

粮小二是数字员工，因此所有 Tab 必须共享一个常驻对话入口：

- 桌面端为右侧 400px 抽屉，可收起。
- 窄屏为底部全屏抽屉。
- 切换 Tab 不清空消息。
- 切换任务时重置任务上下文，但保留可见的任务切换提示。
- 对话消息可引用粮源、供应方、寻源方案和交接确认卡。

默认占位文案：

> 问粮小二，或直接描述找粮需求……

### 6.3 上下文范围

Agent 每轮最多读取：

- 当前会话
- 当前任务及最近一次寻源运行
- 当前 Tab
- 当前筛选条件
- 用户选中的粮源或供应方
- 当前候选篮

Agent 不应无边界读取全部历史任务。

## 7. 粮源市场

### 7.1 演示市场概览

概览从固定 Mock 粮源聚合计算：

- 在架粮源数
- 演示挂牌总量
- 主要品种
- 报价区间（按相同价格口径分别展示）
- 覆盖产区

标题使用“演示市场概览”，不使用“今日真实行情”。概览旁固定说明：

> 以下统计仅基于竞赛演示数据集，不代表真实市场。

### 7.2 搜索与筛选

首屏筛选：

- 关键词：品种、产地、供应方、演示标的号
- 品种
- 产地
- 等级
- 年份
- 价格区间

更多条件：

- 价格口径
- 交收方式
- 最晚可发时间
- 最低可用数量
- 供应方核验状态

任务态自动填充条件，但用户仍可修改。修改条件只改变页面筛选；点击“重新生成方案”并确认后才产生新的运行版本。

### 7.3 粮源列表

桌面端采用高密度表格，主要列为：

- 品种 / 等级 / 年份
- 产地
- 供应方
- 报价与价格口径
- 演示可用数量
- 交收方式
- 最晚可发时间
- 质检摘要
- 数据标签
- 操作

每条粮源固定显示 `演示粮源` 标签。质检、库存、发运和供应方表现不再拆成不同的“演示扩展”表述，因为首版整条记录都是 Mock 数据。

操作仅包含：

- 查看详情
- 加入候选
- 让粮小二分析

### 7.4 右侧市场发现

无任务时展示“粮小二市场发现（基于演示数据）”，只做确定性摘要，例如：

- 哪个品种的演示供应较多
- 哪个产区的粮源更集中
- 哪些粮源字段缺失较多
- 同一价格口径下的高低价区间

这些内容必须标记 `data_kind=inference`，且不得称为个性化推荐。

任务态则显示：

- 当前任务条件
- 已通过硬条件数量
- 当前主推草案
- 当前备选草案
- 生成或重新生成方案入口

### 7.5 粮源详情抽屉

详情分区展示：

- 基本信息
- 报价与数量
- 演示质检指标
- 演示发运条件
- 演示供应方信息
- 待核验清单
- 数据集版本与生成时间

详情顶部固定显示：

> 本记录为竞赛演示数据，实际采购前需核验库存、质量、报价和发运能力。

## 8. 寻源方案

### 8.1 前置条件

没有当前任务时，方案页展示空状态和两个入口：“描述找粮需求”“新建寻源任务”，不生成推荐。

### 8.2 硬条件

首版支持以下硬条件：

- 品种一致
- 数量达到需求
- 等级达到要求
- 年份符合要求
- 报价不超过价格上限
- 最晚可发时间不晚于要求

缺失某个已指定硬条件的数据时，候选按“不确定且不可入选”处理，并生成对应核验项；不能让模型猜测。

### 8.3 候选比较

通过硬条件后按以下顺序比较：

1. 关键字段完整度
2. 价格口径可比性
3. 同口径报价
4. 发运时间余量
5. 供应方演示履约证据完整度
6. 待核验项数量

首版不输出难以解释的综合分，只输出逐项判断和排序理由。

### 8.4 主推与备选

主推与备选卡必须展示：

- 粮源核心字段
- 报价口径
- 演示可用数量
- 质量与发运摘要
- 入选理由
- 主要风险
- 待核验项数量
- `演示数据` 标签

若只有一条满足条件，只展示主推并明确“暂无满足硬条件的备选”。

### 8.5 未入选解释

每条未入选粮源必须至少有一个结构化原因码，例如：

- `VARIETY_MISMATCH`
- `QUANTITY_INSUFFICIENT`
- `GRADE_BELOW_REQUIREMENT`
- `CROP_YEAR_MISMATCH`
- `PRICE_OVER_BUDGET`
- `SHIP_WINDOW_MISSED`
- `REQUIRED_FIELD_MISSING`

自然语言解释由确定性原因模板生成，LangChain 可将其改写得更易懂，但不能改变原因事实。

### 8.6 待核验清单

无论 Mock 数据多完整，方案都默认生成以下交易前核验项：

- 确认可锁定库存
- 获取正式质检单
- 确认报价有效期与含税口径
- 确认装运窗口
- 核验供应方主体与联系人

### 8.7 下一步动作

首版支持：

- 保存当前方案
- 加入或移出候选
- 重新生成方案
- 确认交接运小二

首版不支持：

- 自动联系供应方
- 自动询价
- 自动下单、签约或付款

## 9. 寻源任务

### 9.1 创建方式

任务可来自：

- 粮小二对话提取并确认
- 页面结构化表单
- 瞻小二交接
- 我的办事继续处理

### 9.2 条件字段

- 品种
- 需求数量
- 目标等级
- 年份
- 目标到达地区
- 最高采购价
- 价格口径偏好
- 最晚可发时间
- 其他说明

### 9.3 状态

首版保持简单状态：

- `draft`
- `sourcing`
- `plan_ready`
- `handed_off`
- `closed`

### 9.4 任务详情

任务详情包含：

- 当前条件
- 来源小二和交接摘要
- 历次寻源运行
- 当前主推与备选
- 候选篮
- 待核验项
- 对话记录入口
- 交接状态

修改条件不覆盖历史运行，而是确认后创建新的 `sourcing_run`。

## 10. 供应方

### 10.1 列表

供应方列表由 Mock 粮源聚合，展示：

- 演示供应方名称
- 所在地区
- 关联品种
- 在架粮源数
- 演示可用总量
- 演示履约证据完整度
- 主体核验状态
- `演示数据` 标签

### 10.2 详情

供应方详情包含：

- 演示主体档案
- 关联粮源
- 演示历史履约指标
- 证照、联系人和仓库地址核验状态
- 当前任务中的候选关联

### 10.3 明确不做

- 不做真实企业征信。
- 不展示未经核验的真实联系人。
- 不让供应方表现覆盖具体粮源硬条件。
- 不自动发起联系或询价。

## 11. 对话 Agent

### 11.1 对话意图

粮小二支持：

- 浏览和解释演示粮源
- 提取采购需求
- 补齐缺失条件
- 比较候选粮源
- 解释主推、备选和淘汰原因
- 查看供应方演示档案
- 创建任务确认
- 重新生成方案确认
- 交接运小二确认

### 11.2 LangChain 结构

LangChain 服务必须遵守：

- 系统提示明确当前数据集全部为演示数据。
- 回答涉及库存、质量、报价、发运和履约时，必须提示实际交易前核验。
- 只读工具可直接调用；写工具只生成 `action_proposal`。
- 不展示模型内部思维链，只展示业务步骤摘要。
- 模型失败时不影响市场浏览和确定性寻源。

### 11.3 只读 Tools

- `search_listings(filters)`：搜索演示粮源。
- `get_listing(listing_id)`：读取粮源详情。
- `get_market_summary()`：读取演示市场概览。
- `get_sourcing_task(task_id)`：读取任务条件。
- `get_sourcing_plan(task_id)`：读取最近一次运行结果。
- `compare_candidates(listing_ids, task_id)`：返回确定性对比。
- `get_supplier(supplier_id)`：读取演示供应方档案。

### 11.4 写操作确认

以下动作只能返回确认卡：

- 创建寻源任务
- 更新任务条件
- 生成或重新生成方案
- 保存候选
- 交接运小二

确认卡包含动作、影响对象、结构化参数和风险提示。用户点击确认后，由普通 REST API 执行。

### 11.5 执行摘要

流式状态只显示业务摘要，例如：

- 正在读取当前任务……
- 正在筛选演示粮源……
- 正在比较满足条件的候选……
- 正在整理待核验项……

## 12. Mock 数据设计

### 12.1 数据集要求

固定数据集名称：`liang-v1`。

数据集必须：

- 保存在代码内的显式种子文件中，便于审查和调整。
- 初始化后写入本地 MySQL，页面和 Agent 均从数据库读取。
- 使用稳定唯一键，重复启动幂等。
- 覆盖成功、备选、低价但质量不符、数量不足、字段缺失等不同情况。
- 所有数据为虚构或合成，不使用可能被误认成真实企业的敏感信息。

### 12.2 代表粮源

至少包含以下玉米场景：

1. **北安粮源**：满足数量、等级和发运要求，作为主推。
2. **榆树粮源**：满足硬条件但报价或发运余量略弱，作为备选。
3. **铁岭粮源**：价格更低但等级或质检不满足，用于解释“不是最低价就推荐”。
4. **通辽粮源**：其他条件较好但数量不足，用于硬条件淘汰。
5. **字段缺失粮源**：缺少发运或关键质检字段，用于展示不确定性处理。

同时增加小麦、大豆等少量粮源，保证无任务市场页具有浏览价值。

### 12.3 时间语义

- `mock_dataset_version`：数据集版本，例如 `liang-v1`。
- `mock_generated_at`：固定版本生成时间。
- `updated_at`：本地记录最后修改时间。

首版不设置 `source_published_at`、`fetched_at`、`freshness` 或同步状态，因为不存在外部来源。

### 12.4 页面刷新语义

浏览器重新请求市场接口，只重新读取 MySQL 和重新计算聚合结果。它不是外部数据刷新，因此：

- 不提供“同步公开数据”按钮。
- 不配置后台刷新任务。
- 不显示“实时”“刚刚同步”等容易误导的状态。

## 15. 确定性寻源算法

### 15.1 输入

- 用户确认后的任务条件
- 当前 `liang-v1` Mock 粮源
- 用户手动加入的候选粮源

### 15.2 处理

1. 统一品种、等级、年份和时间格式。
2. 对每条粮源逐项执行硬条件检查。
3. 将失败项记录为结构化原因码。
4. 对通过项计算可解释排序键。
5. 选第一名为主推、第二名为备选。
6. 合并每条候选的默认核验项和缺失字段核验项。
7. 保存运行快照和候选结果。

建议排序键：

```text
(
  required_field_missing_count,
  price_basis_penalty,
  comparable_price,
  ship_time_penalty,
  supplier_evidence_penalty,
  verification_item_count,
  listing_id
)
```

`listing_id` 作为最后稳定排序键，保证竞赛演示结果可复现。

### 15.3 无结果

没有粮源通过硬条件时：

- 不生成伪主推。
- 展示每条最接近粮源的失败原因。
- 给出可操作的放宽建议，例如减少数量、放宽等级或延后发运。
- 放宽条件后仍需用户确认，再创建新的运行版本。

## 16. 异常与降级

### 16.1 Mock 数据未初始化

- 市场页展示“演示数据尚未初始化”。
- 提示检查数据库初始化，不自动访问任何外部来源。
- API 返回可识别的空状态，不伪造统计。

### 16.2 数据字段缺失

- 列表显示 `--`。
- 已指定的硬条件字段缺失时，该粮源不能进入主推或备选。
- 生成 `REQUIRED_FIELD_MISSING` 和对应核验项。

### 16.3 LangChain 或模型失败

- 市场、任务和确定性方案继续可用。
- 对话栏展示可重试提示。
- 不丢失已确认任务、运行和候选结果。

### 16.4 条件不足

- Agent 只追问影响筛选的关键字段。
- 页面保持市场浏览态。
- 条件确认前不创建任务和方案。

### 16.5 交接失败

- 保留粮小二任务和方案。
- 展示失败原因与重试入口。
- 不重复创建同一确认请求对应的运小二交接。

## 17. 测试与验收

### 17.1 Mock 数据

- 固定种子可重复执行且不重复插入。
- 所有粮源和供应方均为 `data_kind=simulated`。
- 数据集版本和生成时间在 API、UI 一致。
- 至少覆盖主推、备选、等级不符、数量不足和字段缺失场景。
- 测试和演示不依赖网络。

### 17.2 寻源规则

- 不满足任一硬条件的粮源不得入选。
- 缺失必填判断字段时不得由模型补全。
- 相同输入得到稳定的主推、备选和淘汰原因。
- 不同价格口径不计算误导性差价。
- 无合格粮源时不生成伪主推。

### 17.3 任务与 Agent

- 独立创建任务和瞻小二交接都能进入相同任务态。
- 修改条件产生新运行，不覆盖历史结果。
- 写操作必须先出现确认卡。
- Agent 必须明确数据为演示数据。
- LangChain 失败时确定性方案仍可打开。
- 粮到运交接可重试且幂等。

### 17.4 前端

- `/agent/liang` 默认显示粮源列表。
- 无任务时不显示个性化推荐。
- 四个 Tab 共用对话上下文。
- 页面、列表、详情、供应方和方案均清晰显示演示数据标识。
- 页面没有公开数据切换、同步按钮或实时状态。
- 窄屏可完成浏览、创建任务、查看方案和确认交接。

### 17.5 端到端代表场景

1. 独立打开粮小二，看到 `liang-v1` 演示市场。
2. 输入“120 吨东北二等玉米，7 天内可发”。
3. 确认创建任务。
4. 北安成为主推，榆树成为备选。
5. 铁岭因等级或质检不符被淘汰，通辽因数量不足被淘汰。
6. 页面展示统一待核验项和“演示数据”标识。
7. 用户确认交接运小二，形成结构化交接任务。

## 18. 首版范围边界

### 18.1 首版必须完成

- 独立粮小二入口
- 四个业务 Tab
- 高密度 Mock 粮源市场
- 固定、幂等、可复现的 `liang-v1` 数据集

- 公开数据接入、解析、抓取或同步
- 后台定时刷新、手动刷新和快照管理
- 公开/演示数据模式切换
- 实时行情或数据新鲜度承诺
- 多粮源组合寻源
- 自动联系、询价、下单、签约或付款
- 到厂成本精算
- 真实企业征信

## 19. 后续真实数据接入方向

公开数据接入仅作为竞赛后的扩展方向，不进入本次实现范围。未来若接入，建议保持 `grain_listings` 领域模型和现有 API 返回结构稳定，新增独立适配器、来源元数据和同步状态，不让页面或 Agent 直接依赖某个站点协议。

接入真实来源后必须重新设计并验收：

- 来源授权与使用边界
- 数据发布时间、获取时间和新鲜度
- 空响应、失败和最后成功快照
- 真实与 Mock 数据隔离
- 页面措辞与字段级证据标签

在这些能力完成前，产品只以明确标识的演示数据运行。
