# 运小二｜首 tab 与页面整体重设计规格

> 日期：2026-08-23
> 状态：已确认
> 范围：运小二完整页面信息架构重设计，以「找物流」智能受理 + 即时测算为首 tab
> 替代：`2026-08-23-yun-xiaoer-design.md`（旧规格中物流市场为首屏的方案作废，业务闭环与规则部分在新规格中收敛保留）

---

## 1. 设计目标

用户点开运小二时，几乎必然带着一批具体的货（或即将有一批货），真实问题是"把这批粮运到厂，多少钱、几天到、找谁运"，而不是"逛逛物流市场"。首版要把这个目标压缩成：**10 秒看到参考运费与时效，并知道下一步做什么**。

首版需要同时接住三种场景：

| 场景 | 用户状态 | 首 tab 承接方式 |
| --- | --- | --- |
| 已有粮要运 | 粮源已确定（或粮小二交接） | 一句话受理 → 即时测算 → 生成正式运输需求 |
| 采购前摸运费 | 比价/选粮源阶段 | 只测算不建任务，多轮对比不同粮源组合，记录可恢复 |
| 看行情 | 无具体批次 | 热门线路参考价快照 + 点击预填受理卡 |

需要解决的真实痛点：

- 运费不透明：粮贸采购者的第一个问题往往是"运过去多少钱、几天到"，参考运价分散难查。
- 用户只有"把这批粮运到厂"的模糊目标，不掌握完整询运条件，容易遗漏时间窗、装卸能力。
- 最低运费不等于最合适方案：跨运输方式比较要考虑时效、换装、超期风险。
- 方案形成后仍需人工重新整理询运需求，信息容易丢失或口径变化。
- AI 若不受结构化数据约束，容易生成不存在的运价与运力。

首版成功标准：

- 用户进入运小二第一眼是受理入口，一句话或五个字段即可得到各运输方式的参考运费与时效。
- 测算与正式方案共用同一份市场数据，口径一致，不出现"测算一个价、方案另一个价"。
- 不满足到货期限的低价方案不能成为主推，并写明淘汰原因。
- 用户可以把选定方案转换成标准询运单并提交人工对接。
- 粮小二交接路径可带上下文预填，走通同一闭环。

---

## 2. 信息架构

四个 Tab，流程型结构，市场数据内嵌为参考依据，不设独立物流市场 Tab：

```text
找物流 → 运输方案 → 询运对接 → 运输任务
```

全局布局沿用现有小二页模式（头部身份 + Tab 条 + 内容区，暗色科技风格）：

```text
┌────────────────────────────────────────────────────────────────┐
│ 运小二｜找物流 / 当前任务摘要（有任务时）/ 切换小二            │
├────────────────────────────────────────────────────────────────┤
│ 找物流  运输方案  询运对接  运输任务                           │
├────────────────────────────────────────────────────────────────┤
│ 当前 Tab 主内容                                                │
└────────────────────────────────────────────────────────────────┘
```

首版不做常驻对话侧栏：首 tab 的自然语言受理输入本身就是 LangChain 的主舞台，方案页配"问运小二"解释入口即可。

## 3. Tab 一：找物流（首 tab）

### 3.1 页面目标

把"我有一批粮要运过去"压缩成"10 秒看到参考运费与时效，并知道下一步做什么"。三种场景在此分流，共用同一个受理入口。

### 3.2 页面结构

**① 受理卡（页面主角，全宽）**

- 大号自然语言输入框，示例占位："例如：120 吨东北二等玉米，锦州港到深圳，一周内要到"
- 可展开快速表单：发货地 / 收货地 / 品种 / 数量 / 最晚到货，五个字段，任意填
- 提交按钮两个，主次分明：
  - 主：**即时测算**——不建任务，秒出结果
  - 次：**直接建运输需求**——跳过测算进正式匹配
- 粮小二交接时：受理卡上方出现交接横幅卡（来源任务、已带入的发货地/品种/数量/发运窗口），字段自动预填，用户确认或修改

**② 即时测算结果（提交后出现）**

- 按运输方式并列卡片：公路 / 铁路 / 水运 / 公水联运（有数据才显示）
- 每张卡：参考运费区间（元/吨）、预计时效、换装次数、业务标签（更省钱 / 更快 / 换装少）
- 若用户给了到货期限：满足的卡片标绿，超期的标 ⚠ 并写明"预计超期 X 天"；超期方案依然展示，但不伪装成可行
- 每张卡注明数据口径与更新时间
- 结果区底部两个动作：**生成正式运输需求**（条件带入运输方案 tab）、**换个条件再算**

**③ 底部双栏**

- 左：热门线路参考价——6~8 条热门线路的运价区间与近期涨跌，点击线路自动预填受理卡
- 右：最近测算——历史测算记录可一键恢复重算；如有进行中任务，置顶"任务进行中"卡片跳转到对应 tab

### 3.3 AI 职责

- 从自然语言抽取结构化条件，生成条件确认卡：已确认事实 / 缺失条件 / AI 的解释（如"一周内"→ 具体最晚到货日期）
- 只追问会改变结果的关键缺失项，一次一个
- 测算数字全部来自后端规则与市场数据，模型只负责理解和解释，不产生任何运价数字

### 3.4 边界

- 测算结果是参考区间，不是报价；不出现"匹配率""最优"等无口径表达
- 测算记录会保存（供恢复），但不创建运输任务
- 页面不出现"模拟数据"字样，只标"参考价 / 数据更新时间"

## 4. Tab 二：运输方案

### 4.1 进入前提

首 tab 生成的正式运输需求（或粮小二交接确认后创建的需求）。页面顶部常驻需求摘要条：起终点、品种吨位、到货期限、来源（独立创建 / 粮小二交接 / 测算转入）、当前状态。

### 4.2 页面内容

- **主推方案卡**：完整路线链（每段运输方式 + 节点）、总费用区间、总时效、换装次数、关键风险、推荐理由摘要
- **备选方案卡**：同结构，标注与主推的核心取舍差异（如"省约 ¥18/吨，但超期风险高"）
- **未入选清单**：折叠展示，每条写明淘汰原因（"超最晚到货 2 天"、"单批吨位不足且不允许分批"）
- **待核验清单**：提交询运前必须人工确认的事项（运力、报价有效期、收货端卸货能力）
- **参考依据**：每个方案可展开，列出引用的市场线路、服务与运价口径（市场数据可见性的落点）
- **问运小二**：轻量解释入口，可答"为什么主推公路不推联运""到货期限放宽 3 天会怎样"（情景问题生成临时测算，不覆盖原任务）
- 无匹配时：展示无结果结论 + 导致无结果的硬条件 + 用户可点选的放宽建议
- 用户选定方案 → "生成询运单"跳转询运对接

### 4.3 比较原则

- 先硬过滤，再比较：覆盖起终、品种适配、吨位、发运窗口、最晚到货、装卸兼容为硬条件，不满足者进未入选，不能因价格低进主推
- 硬条件已保证到货的前提下，可行方案内比较顺序：费用中位 > 时效上限 > 换装复杂度；不设无口径综合评分
- 相同输入、相同数据版本结果稳定；模型只解释结构化结果，不重新排序

---

## 5. Tab 三：询运对接

### 5.1 标准询运单

由选定方案自动生成草稿，全部字段可编辑：品种数量、起终点、时间窗、包装/散粮形态、装卸要求、选定方案与路线、拟对接服务、期望报价口径、需承运方确认的问题。用户确认后才提交人工对接。

### 5.2 状态与反馈

- 状态流转：待用户确认 → 已提交 → 对接中 → 已反馈 → 已结束
- "已提交"只表示进入人工对接流程，不表示接单或锁定运力
- 反馈展示：反馈方、可承运量、报价与计价单位、包含/不包含项、有效期、特别条件
- 新反馈形成新版本，不覆盖原方案，可回到方案页看差异

---

## 6. Tab 四：运输任务

- 统一列表：进行中 / 待确认 / 有发现 / 已提交 / 已反馈 / 已完成 + 测算记录（未建任务的即时测算，可恢复重算或转为正式需求）
- 任务详情时间线：需求创建 → 条件修改 → 匹配 → 方案生成 → 选择 → 询运提交 → 反馈 → 结束，每节点保留当时版本
- 每条展示当前阻塞与下一步动作
- 支持"复制任务重新发起"（只预填条件，不复用旧结论）

### 跨 tab 流转规则

- 当前任务上下文跨 tab 保留，刷新可恢复
- 首 tab → 运输方案的唯一通道是"生成正式运输需求"（用户确认条件卡之后）
- 运输方案 → 询运对接的唯一通道是"选定方案生成询运单"

## 7. 技术设计

### 7.1 模块结构

后端新模块 `backend/app/logistics/`（models.py / repository.py / routes.py / seed.py，在 main.py 注册并加入启动 seed）；前端新模块 `web/src/features/yun/`，在 `AgentServicePage` 中挂载（参照 ZhanPage 模式）；`agents.ts` 中运小二 tabs 更新为「找物流、运输方案、询运对接、运输任务」。

### 7.2 数据对象（首版最小集）

1. **物流线路段 `route_segment`**：起点、终点、运输方式（公路/铁路/水运）、里程区间、参考运价区间（元/吨）+计价单位、预计时效区间、换装要求、风险备注、数据更新时间
2. **物流服务 `logistics_service`**：承运方、运输方式、覆盖线路（关联线路段）、适用品种、可承运吨位区间、发运窗口、装卸条件、履约表现摘要（文字摘要，不做评分体系）
3. **即时测算 `quick_estimate`**：条件快照（起终点/品种/数量/到货期限）、各方式测算结果、数据版本、创建时间——只存记录，不产生任务
4. **运输任务 `transport_task`**：需求字段、来源类型（独立/交接/测算转入）、来源标识、当前状态、当前阻塞、时间戳
5. **运输方案 `transport_plan`**：任务关联、类型（主推/备选/未入选）、路线段组合、费用时效汇总、推荐或淘汰原因、待核验清单、引用的线路段与服务
6. **询运单 `inquiry` + 反馈 `feedback`**：询运字段、关联任务与方案、状态、反馈列表（版本化，不覆盖）

### 7.3 两层计算规则

- **即时测算（轻量层）**：按运输方式聚合——对每种方式查覆盖该起终点对的线路段，直接给运价区间和时效区间。不做硬过滤、不组合完整多式联运、不选主推，只回答"大概多少钱、几天到"。公水联运 = 公路段 + 水运段的简单拼接展示，并标注换装节点。
- **正式匹配（完整层）**：进入运输方案 tab 后执行——硬条件过滤 → 路线段组合 → 费用时效汇总 → 按比较原则排序 → 产出主推/备选/未入选+原因。

两层共用同一份线路段与服务数据，保证测算与正式方案口径一致。

### 7.4 接口草案（/api/logistics）

- `POST /estimates` 即时测算（入参条件，出参各方式结果）
- `GET /estimates`、`GET /estimates/{id}` 测算记录
- `GET /hot-routes` 热门线路快照
- `POST /tasks` 创建运输需求（含确认卡数据）
- `POST /tasks/{id}/match` 触发正式匹配；`GET /tasks/{id}/plans`
- `POST /plans/{id}/inquiry` 生成询运单草稿；`POST /inquiries/{id}/submit` 提交；反馈用 seed 预置模拟
- `GET /tasks` 任务列表与详情

### 7.5 LangChain 集成

复用 `app/analysis/llm.py` 现有模式，提供两个能力：

- 自然语言抽取结构化条件（输出 JSON + 置信说明）
- 解释主推/备选/淘汰原因（基于结构化结果组织语言）

模型不调用写接口。

### 7.6 Mock 数据原则

- 线路覆盖真实粮贸主干线：东北产区（哈尔滨/长春/白城）→ 锦州港/鲅鱼圈 → 华南港口（深圳/广州/蛇口）→ 销区到厂；公路直发线路若干
- 运价贴近现实量级：公路约 0.35~0.5 元/吨公里折算、铁路约 0.15~0.2、水运约 0.05~0.1，多式联运分段相加加换装费
- 页面不出现"模拟数据"字样，只标"参考价 / 数据更新时间"

## 8. 确认边界

需要用户确认的动作（页面按钮触发，AI 不能代办）：

- 确认条件卡 → 创建运输需求
- 选定主推/备选方案
- 确认询运单内容 → 提交人工对接
- 放宽硬条件后重新匹配
- 复制历史任务/测算重新发起

无需确认的只读动作：即时测算、浏览热门线路、查看方案与依据、问运小二解释。

---

## 9. 异常与降级

- 起终点/品种缺失：不硬算，展示缺失项与一个最关键补问（如"这批货最晚什么时候要到厂？"）
- 无线路覆盖：测算卡明确写"该起终点暂无参考线路"，给相邻港口/节点建议
- 超期方案：展示但标 ⚠，进不了主推；正式匹配中进未入选清单并写明原因
- LLM 不可用：受理输入降级为快速表单，解释降级为结构化模板文案，测算与匹配规则不受影响（纯后端规则）
- 后端/数据未就绪：沿用现有页面模式提示"数据未就绪"，不伪造结果

---

## 10. 验收标准（代表场景）

> 120 吨东北二等玉米，锦州港运到深圳，7 天内到货。

1. 用户一句话输入 → 秒出各方式参考运费与时效，水运/联运标注超期风险
2. 点击"生成正式运输需求" → 条件确认卡补齐缺失项 → 创建任务
3. 运输方案产出主推（公路或公铁）+ 备选 + 未入选（纯海运超期）+ 待核验清单
4. "问运小二"能解释推荐理由与低价方案落选原因
5. 选定方案 → 询运单草稿可编辑 → 确认提交 → 任务时间线完整可查
6. 粮小二交接路径：带上下文预填，同样能走通闭环
7. 刷新页面后任务与测算记录可恢复

## 11. 首版明确不做

实时轨迹、自动下单/订舱、承运商后台、运价预测、常驻对话侧栏、独立物流市场 tab。
