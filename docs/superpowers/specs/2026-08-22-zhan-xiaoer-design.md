# 瞻小二｜看行情——页面与 Agent 设计规格

> 日期：2026-08-22  
> 状态：已确认，按竞赛稳定演示范围调整  
> 范围：瞻小二独立服务页、市场全景、品种行情、采购研判、我的关注、研判记录、常驻对话 Agent、固定 Mock 数据与粮小二交接

---

## 1. 设计目标

瞻小二是粮达网 Plus 中负责行情理解和采购时机研判的 AI 数字员工。页面既服务暂时没有采购计划、只想了解市场的用户，也服务已有采购任务、需要判断“现在怎么买”的用户。

首版要解决的真实问题：

- 行情信息散落在价格曲线、区域报价、库存、到货、政策和事件中，采购人员难以形成统一判断。
- 用户真正需要的不是“涨了还是跌了”，而是建议采购节奏、理由、风险和下一步动作。
- AI 研判必须能追溯到结构化指标，不能仅输出一段不可验证的观点。
- 研判结果要能直接形成粮小二可承接的结构化找粮任务。

竞赛阶段成功标准：

- 演示不依赖外部网站、接口响应、网络状态或定时同步。
- 四个品种的市场页面具有完整、可信的演示层次。
- 玉米采购场景可以稳定生成明确研判并交接粮小二。
- 价格、事件、用户输入和 AI 推断边界清楚。
- LangChain 对话和页面研判共享同一业务上下文。

代表场景：

> 用户需要在未来 15 天内采购 120 吨东北二等玉米。瞻小二结合固定演示价格曲线、区域价差、库存与到货指标、关键事件，给出“分两批采购、先锁定 40%～60%”的演示建议，并在用户确认后生成粮小二预填任务。

## 2. 已确认的核心决策

### 2.1 数据策略：Mock-first

由于首版用于 AI 竞赛，稳定演示优先，暂不接入任何公开行情或资讯来源：

- 价格历史、区域价格、成交/库存/到货指标、关键事件和辅助指标全部使用固定 Mock 数据。
- 数据随应用初始化写入本地 MySQL，页面、规则和 Agent 从同一份数据库数据读取。
- 固定数据集名称为 `zhan-v1`，使用稳定业务唯一键和固定版本生成时间。
- 所有 Mock 事实统一标记 `data_kind=simulated`。
- 用户采购需求和关注条件标记 `data_kind=user_input`。
- 确定性指标、规则结论和 AI 解释标记 `data_kind=inference`。
- UI 常驻显示“当前为演示行情”，不得写“实时行情”“官方价格”“公开事实”或“刚刚同步”。
- 首版不做公开源客户端、网页解析、定时同步、手动刷新、最后成功快照、数据新鲜度或公开/演示模式切换。

页面常驻展示：

- `当前为演示行情`
- `演示数据集：zhan-v1`
- `数据生成时间：2026-08-22 10:00`
- `以下内容不代表真实市场，不可直接作为交易依据`

### 2.2 页面与对话并重

瞻小二不是只有聊天窗口。默认页面必须展示可浏览、可比较的市场全景；对话栏常驻并能读取当前 Tab、品种、区域、时间范围和采购任务。

### 2.3 行动建议必须具体

采购研判至少回答：

- 当前建议：立即采购、分批采购、等待或先核验。
- 建议采购比例与时间窗口。
- 支持建议的结构化证据。
- 反对建议或可能失效的因素。
- 需要继续观察的指标。
- 是否交接粮小二开始找粮。

### 2.4 Agent 框架

所有 Agent 能力统一使用 LangChain：

- LangChain 负责理解问题、选择只读工具和解释确定性结果。
- 价格变化、区域价差、趋势方向、关注触发和采购建议骨架由普通 Python 规则计算。
- 模型不能直接修改关注、研判记录或交接状态。
- 写操作先生成确认卡，用户确认后由 REST API 执行。

## 3. 产品原则

### 3.1 没有采购需求也有完整价值

用户直接打开 `/agent/zhan` 时默认进入“市场全景”，可以浏览四个品种、趋势、区域价格、事件和演示市场判断，不要求先创建采购任务。

### 3.2 事实、输入与推断分层

首版只有三类数据：

- **演示事实**：固定 Mock 价格、指标和事件，`data_kind=simulated`。
- **用户输入**：采购条件和关注阈值，`data_kind=user_input`。
- **系统推断**：趋势、价差、影响方向和建议，`data_kind=inference`。

不再保留“公开事实”类别用于瞻小二首版。

### 3.3 不制造虚假精确度

- 不把 Mock 行情写成当前真实行情。
- 不用一个无法解释的综合分替代证据。
- 数据缺失时显示缺失，不让模型补值。
- 结论必须同时展示支持和反对依据。
- 置信度由证据完整度和规则一致性决定，不由模型自由声明。
- 不在不同等级、区域或价格口径间直接计算误导性价差。

### 3.4 用户确认后才改变业务状态

创建关注、保存研判、修改条件和交接粮小二必须先展示确认卡。页面筛选、图表切换和只读问答无需确认。

### 3.5 控制首版范围

首版完成看行情、做研判、设关注、留记录和交接找粮，不做真实交易执行、自动采购、自动通知外部联系人或价格预测模型训练。

## 4. 页面信息架构

页内采用五个 Tab：

1. **市场全景**：默认入口，展示多品种市场脉搏和总体判断。
2. **品种行情**：深入查看单品种价格、区域差异和驱动因素。
3. **采购研判**：输入采购条件，生成可执行建议。
4. **我的关注**：管理价格和指标关注条件。
5. **研判记录**：查看历史研判、条件快照和交接状态。

共通布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 瞻小二 / 当前品种 / 当前任务 / 演示行情标识 / 对话入口       │
├──────────────────────────────────────────────────────────────┤
│ 市场全景  品种行情  采购研判  我的关注  研判记录             │
├────────────────────────────────────────────┬─────────────────┤
│ 当前 Tab 主内容                            │ 瞻小二对话抽屉  │
│                                            │ 可收起、跨 Tab  │
│                                            │ 保留上下文      │
└────────────────────────────────────────────┴─────────────────┘
```

## 5. 共通页面框架

### 5.1 页面头部

包含：

- 瞻小二图标、名称和职责。
- 当前选中品种。
- 当前采购任务摘要或“尚未创建采购研判”。
- 琥珀色常驻标签：`当前为演示行情`。
- `zhan-v1` 版本与数据生成时间。
- 对话展开/收起按钮。

不提供外部数据刷新按钮。页面重新请求 API 只重新读取本地 MySQL 和计算指标。

### 5.2 常驻对话栏

- 桌面端为右侧 400px 抽屉，可收起。
- 窄屏为底部全屏抽屉。
- 切换 Tab 或品种不清空消息。
- 当前品种、区域、时间范围、研判和选中事件会进入对话上下文。
- 对话消息可引用价格点、事件、采购研判和操作确认卡。

默认占位文案：

> 问瞻小二行情，或描述你的采购计划……

### 5.3 对话能力

支持：

- 解释当前品种走势。
- 比较地区和价格口径。
- 解释关键事件及其演示影响。
- 收集采购条件。
- 生成或解释采购研判。
- 创建关注确认卡。
- 保存研判确认卡。
- 交接粮小二确认卡。

## 6. 市场全景

### 6.1 品种行情脉搏

默认展示：

- 玉米
- 小麦
- 大豆
- 稻谷

每个品种显示：

- 当前演示价格。
- 数据集内日变化、周变化。
- 演示成交或供应强弱。
- 规则化方向标签。
- 证据完整度。
- `演示行情` 标签。

默认选中玉米。切换品种后，曲线、区域价格、事件和判断同步更新。

### 6.2 价格主图

默认展示 30 天曲线，可切换 7 天、30 天、90 天。图表必须显示：

- 品种、等级。
- 地区。
- 价格口径。
- 是否含税、是否含运。
- 单位。
- 演示数据集版本。
- 关键事件标记。

事件点击后更新右侧解释。首版曲线来自固定时间序列，不根据当前系统日期滚动生成随机值。

### 6.3 瞻小二市场判断

右侧判断包含：

- 一句话方向。
- 2～4 条支持依据。
- 1～3 条反对依据或不确定因素。
- 证据完整度。
- 建议继续观察的指标。
- “让瞻小二结合采购计划研判”入口。

该判断由确定性指标生成骨架，LangChain 负责解释。标题使用“瞻小二演示判断”，不使用“今日真实判断”。

### 6.4 重点区域价格

按相同品种、等级和价格口径展示：

- 区域。
- 当前演示价格。
- 数据集内变化。
- 与基准区域价差。
- 交付口径。
- 影响解释。

若口径不同，显示“口径不同，暂不直接比较”。

### 6.5 关键事件与预期影响

事件卡展示：

- 标题。
- 事件日期。
- 演示事件摘要。
- 影响品种与地区。
- 预期方向与强度。
- 作用时间窗。
- 支撑指标。
- `演示事件` 标签。

事件内容为 Mock 事实，影响方向属于 `inference`。不得伪造外部来源链接。

### 6.6 下一步

无任务时：

- 查看品种详情。
- 描述采购计划。
- 创建价格关注。

有任务时：

- 查看采购研判。
- 保存研判。
- 确认交接粮小二。

## 7. 品种行情

### 7.1 筛选条件

- 品种。
- 地区。
- 等级。
- 价格口径。
- 7/30/90 天时间范围。
- 指标类型。

筛选区固定显示 `zhan-v1 演示数据`，不显示公开/模拟数量或来源入口。

### 7.2 核心指标

- 最新演示价。
- 日变化和周变化。
- 区域价差。
- 演示成交/到货/库存指标。
- 波动区间。
- 证据完整度。

所有变化和价差由后端确定性计算。

### 7.3 价格形成链

以轻量链路展示：

```text
产区供给 → 收购/贸易 → 库存与到货 → 区域价格 → 采购窗口
```

每个节点显示对应演示指标、方向和解释。缺少指标时显示“演示数据集中未提供”。

### 7.4 四类驱动因素

- 供给。
- 需求。
- 库存与物流。
- 政策/事件。

每类展示支持与反对证据，不输出单一神秘评分。

### 7.5 继续动作

- 让瞻小二解释当前变化。
- 带入采购研判。
- 创建关注。
- 查看相关历史研判。

## 8. 采购研判

### 8.1 输入条件

必填：

- 品种。
- 采购数量。
- 最晚采购或使用时间。

可选：

- 等级。
- 目标地区。
- 预算或最高价格。
- 已有库存可用天数。
- 价格口径。
- 风险偏好。
- 其他说明。

从其他小二或我的办事进入时可预填，但用户仍需确认。

### 8.2 生成过程

1. 校验必填条件。
2. 读取对应品种的 Mock 价格、区域、指标和事件。
3. 普通 Python 计算趋势、价差、波动和证据完整度。
4. 确定性规则生成行动建议骨架。
5. LangChain 组织支持、反对依据和自然语言解释。
6. Pydantic 校验结构化输出。
7. 用户确认后保存研判记录。

模型失败时，步骤 1～4 的规则化结果仍可展示。

### 8.3 结果结构

- **结论**：立即采购、分批采购、等待或先核验。
- **建议比例**：例如先锁定 40%～60%。
- **建议时间窗**。
- **支持依据**。
- **反对依据与失效条件**。
- **需要关注的指标**。
- **数据缺失项**。
- **证据完整度**。
- **演示数据声明**。
- **下一步动作**。

比例使用区间，不制造精确到个位数的假象。

### 8.4 后续动作

- 保存研判。
- 修改条件并重新研判。
- 创建关注。
- 确认交接粮小二。

交接只携带采购条件、研判摘要和需要找粮的结构化约束，不替粮小二选择最终粮源。

## 9. 我的关注

首版支持：

- 价格高于/低于阈值。
- 日变化或周变化超过阈值。
- 区域价差超过阈值。
- 指标方向发生变化。
- 指定演示事件出现。

关注状态：

- `monitoring`：当前 Mock 行情未满足。
- `triggered`：当前 Mock 行情已满足。
- `paused`：用户暂停。
- `closed`：用户关闭。
- `data_pending`：当前数据集缺少判断所需字段。

首版没有不断变化的外部行情，因此不做定时轮询。关注在以下时机用当前 Mock 数据立即重算：

- 用户确认创建或修改关注时。
- 用户打开“我的关注”时。
- 用户点击“重新检查”时。

“重新检查”只重跑确定性条件，不刷新或改变 Mock 数据。满足条件的关注同步到“我的办事”待确认状态。

## 10. 研判记录

记录保存：

- 用户输入快照。
- 使用的数据集版本。
- 使用的指标和事件 ID。
- 确定性指标快照。
- 结构化研判结果。
- 保存时间。
- 后续关注状态。
- 粮小二交接状态。

重新研判创建新记录，不覆盖历史记录。用户可以从记录恢复条件并再次研判。

## 11. Mock 数据设计

### 11.1 数据集要求

固定数据集：`zhan-v1`。

必须满足：

- 数据在代码中的显式种子文件维护。
- 初始化后写入本地 MySQL。
- 稳定业务唯一键，重复启动幂等。
- 固定价格序列和固定事件，不使用随机数。
- 覆盖四个品种和主要区域。
- 覆盖上涨、下跌、震荡、证据不足等不同解释场景。
- 所有内容为合成演示数据，不使用可能被误认为真实行情的当前机构或企业信息。

### 11.2 代表数据

玉米场景至少包含：

- 30 天产区演示价格曲线。
- 东北、华北、港口等同口径区域价格。
- 到货量、库存、成交或供应强弱指标。
- 两条支持阶段性偏强的事件。
- 一条可能压制价格的反对事件。
- 支持“15 天采购窗口、分两批采购”的确定性规则输入。

其他品种：

- 小麦：震荡场景。
- 大豆：偏弱场景。
- 稻谷：数据较少、证据不足场景。

### 11.3 时间语义

- `mock_dataset_version=zhan-v1`。
- `mock_generated_at=2026-08-22 10:00+08:00`。
- 每个价格点和事件有固定 `observed_at` 或 `event_at`，表示演示时间轴上的业务时间。
- `updated_at` 仅表示本地记录修改时间。

首版不设置 `source_published_at`、`fetched_at` 或 `freshness`。

### 11.4 页面重载语义

页面重载或 API 重试只重新读取 MySQL 并计算指标：

- 不访问外部来源。
- 不改变数据集。
- 不显示同步状态。
- 不承诺真实时间上的持续更新。

## 12. 技术架构

### 12.1 总体结构

```text
React
  ├─ 市场与研判 REST API
  ├─ Agent NDJSON 流
  └─ 确认式写操作
        ↓
FastAPI
  ├─ market：Mock 行情、指标和事件
  ├─ workflow：研判、关注、会话、交接
  ├─ agent：LangChain 瞻小二
  └─ mock_seed：zhan-v1 幂等初始化
        ↓
本地 Docker MySQL
```

首版不引入消息队列、向量数据库、独立流系统、行情调度器或多 Agent 编排平台。

### 12.2 LangChain Agent

只读 Tools：

- `get_market_overview(variety_code)`
- `get_price_series(variety_code, region_code, range)`
- `get_region_prices(variety_code)`
- `get_market_events(variety_code)`
- `get_procurement_context(analysis_id)`
- `get_watch_conditions()`
- `get_analysis_record(record_id)`

确定性工具：

- `compute_market_metrics(...)`
- `build_procurement_judgment(...)`
- `evaluate_watch_condition(...)`

写操作不作为可直接执行的 Tool，只返回 `ActionProposal`。

### 12.3 结构化输出

采购研判：

```text
ProcurementJudgment
├─ action
├─ purchase_ratio_range
├─ time_window
├─ supporting_evidence[]
├─ opposing_evidence[]
├─ invalidation_conditions[]
├─ watch_metrics[]
├─ missing_data[]
├─ evidence_completeness
└─ mock_data_notice
```

操作提案：

```text
ActionProposal
├─ action_type
├─ summary
├─ payload
├─ affected_objects[]
├─ warning
└─ request_token
```

### 12.4 会话上下文

每轮最多读取：

- 当前会话。
- 当前 Tab。
- 当前品种、地区和时间范围。
- 当前采购研判。
- 用户选中的价格点或事件。
- 最近一次相关研判记录。

不无边界加载全部记录。

## 13. 最小数据模型

1. `market_prices`：品种、等级、区域、价格口径、数值、单位、演示时间、Mock 版本。
2. `market_metrics`：品种、区域、指标类型、数值、单位、演示时间、Mock 版本。
3. `market_events`：标题、摘要、品种、地区、演示事件时间和 Mock 版本。
4. `analysis_records`：用户条件快照、指标快照、结构化研判和规则版本。
5. `watch_conditions`：关注条件、状态、最近检查时间和触发说明。
6. `agent_threads`、`agent_messages`：复用统一会话体系。
7. `handoff_tasks`：复用跨小二交接体系。

`market_prices`、`market_metrics`、`market_events` 的 `data_kind` 首版固定为 `simulated`。事件影响方向等推断保存在响应或研判快照中，不覆盖 Mock 事实。

## 14. API 边界

### 14.1 市场只读 API

- `GET /api/market/overview`
- `GET /api/market/varieties/{variety_code}`
- `GET /api/market/varieties/{variety_code}/prices`
- `GET /api/market/varieties/{variety_code}/regions`
- `GET /api/market/varieties/{variety_code}/events`

统一返回：

- `data_kind: "simulated"`
- `mock_dataset_version: "zhan-v1"`
- `mock_generated_at`

首版没有刷新、同步和数据源接口。

### 14.2 研判与关注 API

- `POST /api/analysis/preview`
- `POST /api/analysis`
- `GET /api/analysis`
- `GET /api/analysis/{id}`
- `POST /api/analysis/{id}/handoffs/liang`
- `GET /api/watches`
- `POST /api/watches`
- `PATCH /api/watches/{id}`
- `POST /api/watches/{id}/evaluate`

`preview` 只计算不写库；保存、关注和交接接口需要 `request_token`。

### 14.3 Agent API

复用统一会话和流式消息入口，根据 `agent_id=zhan` 分派 LangChain 服务。支持证据引用、研判引用和确认卡事件。

### 14.4 明确不实现

- `/api/market/refresh`。
- 公开来源同步状态接口。
- 定时更新管理接口。
- 自动下单或自动通知外部联系人的接口。

## 15. 异常与降级

### 15.1 Mock 数据未初始化

- 市场页显示“演示行情尚未初始化”。
- API 返回可识别空状态。
- 提示检查本地数据库初始化。
- 不访问公开来源或临时随机生成行情。

### 15.2 部分指标缺失

- 图表隐藏无法绘制的序列。
- 指标显示 `--` 和缺失说明。
- 研判降低证据完整度。
- 缺少关键输入时不输出强行动建议。

### 15.3 LangChain 或模型失败

- 市场全景、图表和确定性指标继续可用。
- 采购研判展示规则化建议骨架。
- 对话栏显示重试提示。
- 已保存记录和交接状态不丢失。

### 15.4 结构化输出不合法

- 使用 Pydantic 校验。
- 允许一次受控修复。
- 仍失败则回退到确定性结果，不保存无效结构。

### 15.5 关注条件无法检查

- 状态设为 `data_pending`。
- 明确显示缺失字段。
- 不把无法判断误报为“未触发”。

## 16. 首版范围

### 16.1 必须完整实现

- 瞻小二独立入口与五个 Tab。
- 固定、幂等、可复现的 `zhan-v1` 数据集。
- 四品种市场全景。
- 玉米完整行情与采购研判闭环。
- 区域价格、演示事件和驱动因素。
- LangChain 常驻对话。
- 确定性指标与建议骨架。
- 关注条件即时检查。
- 研判记录。
- 确认式交接粮小二。
- 我的办事联动。
- 无网络依赖的端到端演示。

### 16.2 轻量实现

- 小麦、大豆、稻谷提供足以支持全景和基本解释的数据。
- 关注只做产品内状态，不做短信、邮件或外部推送。
- 研判采用规则与 LangChain 解释，不训练预测模型。

### 16.3 本轮不实现

- 公开行情、资讯或事件接入。
- HTTP 抓取、解析和同步。
- 后台定时刷新、手动数据刷新和快照。
- 数据新鲜度或实时行情承诺。
- 公开/演示模式切换。
- 多模型或多 Agent 编排平台。
- 自动采购、下单、签约和付款。
- 真实价格预测模型。

## 17. 测试与验收

### 17.1 Mock 数据

- 种子重复执行不重复插入。
- 所有行情、指标和事件均为 `simulated`。
- 数据集版本和生成时间在 API、UI 一致。
- 固定曲线、事件和指标不使用随机数。
- 测试和演示不依赖网络。

### 17.2 确定性计算

- 日变化、周变化和区域价差正确。
- 不同口径不直接比较。
- 趋势和证据完整度可复现。
- 玉米代表条件稳定得到“分批采购”建议。
- 数据不足时不返回强行动建议。
- 关注条件判断稳定且缺失数据进入 `data_pending`。

### 17.3 Agent 与工作流

- LangChain Tools 只读。
- AI 明确说明使用演示行情。
- 写操作必须先确认。
- 保存研判产生条件和证据快照。
- 交接粮小二包含采购约束和 Mock 声明。
- 模型失败时规则化研判仍可用。

### 17.4 前端

- `/agent/zhan` 默认显示市场全景。
- 五个 Tab 可切换且对话不丢失。
- 页面、图表、事件、研判和记录均清晰显示演示数据。
- 不存在公开来源链接、同步按钮或实时状态。
- 桌面和窄屏均能完成核心闭环。

### 17.5 核心闭环

1. 独立打开瞻小二并看到 `zhan-v1` 市场全景。
2. 查看玉米 30 天曲线、区域价差和演示事件。
3. 输入“15 天内采购 120 吨东北二等玉米”。
4. 得到稳定的分批采购建议、支持/反对证据和失效条件。
5. 确认保存研判。
6. 创建并即时检查价格关注。
7. 确认交接粮小二。
8. 从我的办事重新进入对应任务。

## 18. 后续真实数据接入方向

真实行情接入仅作为竞赛后的扩展方向，不进入本次实现范围。未来接入时应通过独立适配器写入现有市场领域模型，页面和 Agent 不直接依赖具体站点协议。

接入前必须重新设计并验收：

- 数据授权和使用边界。
- 来源发布时间、获取时间和新鲜度。
- 同品种、等级、地区和口径标准化。
- 失败、空响应和最后成功快照。
- 真实与 Mock 数据隔离。
- 关注任务的持续更新机制。
- 页面证据标签和免责声明。

在这些能力完成前，瞻小二只以明确标识的 `zhan-v1` 演示行情运行。
