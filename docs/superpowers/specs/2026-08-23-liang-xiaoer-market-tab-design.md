# 粮小二第一 Tab「找粮源」——粮源市场设计规格

> 日期：2026-08-23
> 状态：已确认
> 范围：粮小二默认入口「找粮源」Tab 的粮源市场页面，含候选篮与「我要找粮」输入框这两个跨 Tab 组件的首屏形态。候选对比、供应方、寻源任务、历史记录不在本文档范围。

---

## 1. 设计目标与真实痛点

粮小二的定位是「粮源寻采」。采购员打开粮小二的第一刻，最典型的场景是**先逛市场，看看现在有什么粮、什么价、从哪来，再决定要不要下单寻源**。

真实痛点：

- 粮源信息分散，需要反复整理品种、等级、数量、价格口径和交收条件。
- 价格口径混乱——有人报出厂价、有人报到库价、有人报港口价，无法直接比较。
- 供应商真假难辨，最低价不一定满足质量、数量和发货能力。
- 逛完市场缺一个「下一步」，不知道从「看」如何转到「定」。

第一 Tab 要回答的问题：**打开就能干正事，先看清市场在卖什么，再自然进入寻源。**

---

## 2. 已确认的核心决策

1. **内容优先**：第一 Tab 是「粮源市场」浏览，不是聊天欢迎页，也不是需求表单。
2. **粮小二主动给「市场发现」**：右侧常驻确定性洞察（哪个品种多、哪个产区集中、哪些字段缺失），但不做个性化推荐。
3. **输入框 + 候选篮都要**：顶部常驻「我要找粮」输入框，列表每条「加入候选」，形成「逛 → 收藏 → 生成方案」闭环。
4. **候选篮是全局浮动组件**：右下角气泡常驻，跨 Tab 共享；出结论在第二个 Tab「候选对比」，不在第一 Tab。
5. **不显眼标注 Mock**：页面不出现「演示数据 / 演示粮源 / 数据集版本」等字样，像真实产品一样展示，数据本身 mock 但真实感足够（见第 13 节）。

---

## 3. 页面定位与 Tab 职责切分

粮小二现有 Tab 结构（`web/src/data/agents.ts`）：

| Tab | 职责 | 核心内容 |
|---|---|---|
| **找粮源**（第一） | **逛**：纯市场浏览 | 概览 + 筛选 + 列表 + 市场发现 + 加入候选 |
| 候选对比 | **比和定**：出结论 | 候选对比 + 主推/备选/淘汰原因/待核验 |
| 供应方 | 查主体 | 供应方档案 |
| 寻源任务 | 跟进度 | 任务及其运行记录 |
| 历史记录 | 回看 | 历史任务/方案 |

第一 Tab 只做「逛 + 发现 + 收藏」，不产生主推/备选，不落任务。

## 4. 整体布局（三栏）

```text
┌──────────────────────────────────────────────────────────────┐
│ 粮小二｜找粮源                                [切换小二]     │
├──────────────────────────────────────────────────────────────┤
│ 🔍 我要找粮：["120吨二等玉米，7天内可发"…]           [发送]  │
├──────────────────────────────────────────────────────────────┤
│ 概览条：在架粮源 38 ｜ 挂牌 2.4万吨 ｜ 玉米·大豆·小麦 ｜ …   │
├────────────┬─────────────────────────────────┬───────────────┤
│ 筛选器      │ 粮源列表（高密度表格，主体）      │ 粮小二市场发现 │
│            │ · 品种/等级/产地/价格(口径)/数量 │ · 玉米供应集中 │
│            │ · 每条：「+候选/让粮分析/详情」   │ · 东北产区占6成│
│            │                                │ · 3条缺质检   │
└────────────┴─────────────────────────────────┴───────────────┘
                                    右下角浮动：🛒 候选篮(0)
```

- 桌面端三栏：左筛选、中列表、右市场发现。
- 窄屏（<lg）降级为单列：筛选收进折叠面板，市场发现移到列表上方，候选篮仍为右下角气泡。

---

## 5. 概览条

顶部统计条，一眼看清市场在卖什么：

- 在架粮源数
- 挂牌总量（吨）
- 主要品种
- 报价区间（**按同一价格口径分别列**，不混着比）
- 覆盖产区

措辞真实，不写「演示数据」，例如「今日在架 38 笔」「挂牌总量 2.4 万吨」。

---

## 6. 筛选器（左栏）

**常用**：

- 关键词（品种 / 产地 / 供应方 / 标的号）
- 品种
- 产地
- 等级
- 年份
- 价格区间

**更多**：

- 价格口径（出厂价 / 到库价 / 港口价）
- 交收方式（散粮 / 集装箱 / 车板）
- 最晚可发时间
- 最低可用数量
- 供应方核验状态

筛选只作用于当前列表视图，不创建任务。清空筛选恢复完整市场。

---

## 7. 粮源列表（中栏，主体）

高密度表格，列：

| 品种·等级·年份 | 产地 | 供应方 | 报价（口径） | 可用量 | 交收 | 最晚可发 | 质检摘要 | 操作 |
|---|---|---|---|---|---|---|---|---|
| 玉米·二等·2025 | 黑龙江绥化 | 北安粮贸 | 2,380（出厂价） | 800吨 | 散粮 | 08-28 | 水分14% 容重686 | +候选 · 分析 |

要点：

- 价格口径直接标在报价旁，一眼分清「出厂价 / 到库价 / 港口价」，不同口径不直接比价。
- 质检摘要只展示 2–3 个关键指标（水分 / 容重 / 杂质），完整指标进详情。
- 每条操作：**加入候选 / 让粮小二分析 / 查看详情**。
- 数据缺字段时显示 `--`，不编造。

详情抽屉分区：基本信息、报价与数量、质检指标、发运条件、供应方信息、标的号与更新日期。

---

## 8. 粮小二市场发现（右栏）

基于当前数据集做**确定性摘要**，不写「为你推荐 / 匹配率」：

- 哪个品种供应最多
- 哪个产区最集中
- 哪些粮源缺质检 / 缺发运窗口
- 同一价格口径下的高低价区间

每条洞察可点击，点击后联动列表筛选（如「东北产区占 6 成」→ 列表只显示东北）。让粮小二有存在感，但不撒谎、不个性化。

---

## 9. 候选篮（右下角浮动气泡，全局常驻）

- 气泡显示当前候选数量，点开为侧边抽屉，列出已收藏粮源。
- 抽屉底部主按钮「**去对比生成方案**」→ 跳转第二个 Tab「候选对比」。
- 候选篮为**前端全局状态**（跨 Tab 共享），首版不落库；持久化与「生成方案」的落库由「候选对比」Tab 决定，第一 Tab 只负责「加 / 减」。

---

## 10. 「我要找粮」输入框（顶部常驻）

- 顶部常驻，任何 Tab 可见；在「找粮源」里说需求 → 粮小二提取条件（品种 / 数量 / 等级 / 时间 / 价格）→ **跳转到「候选对比」Tab 出主推 / 备选**。
- 「出方案」的物理动作在第二个 Tab，但入口第一屏随时可达。
- 首版输入框先做「识别需求并跳转」的轻量形态，不展开完整对话流（对话流归后续统一 Agent 入口）。
- 条件提取首版用**确定性规则**（正则/关键词抽取品种、数量、等级、时间、价格），不接 LLM，保证可复现；LLM 对话留到统一 Agent 入口再接入。

---

## 11. 数据模型

首版只建一张表 `grain_listings`，供应方名称内嵌字段，不建关联表（避免过度设计）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 主键 |
| listing_code | str(64) | 标的号，唯一，如 `LN20250823-001` |
| variety_code / variety_name | str(32) | 品种 |
| crop_year | int | 年份 |
| origin_province / origin_city | str(64) | 产地 |
| grade | str(16) | 等级，如 二等 |
| price | Numeric(10,2) | 报价（元/吨） |
| price_type | str(16) | 口径：出厂价 / 到库价 / 港口价 |
| available_quantity_tons | int | 可用量（吨） |
| delivery_type | str(16) | 交收：散粮 / 集装箱 / 车板 |
| earliest_ship_at / latest_ship_at | date | 发运窗口 |
| moisture_pct / test_weight_g_l / impurity_pct | Numeric | 质检（水分 / 容重 / 杂质） |
| supplier_name / supplier_region | str(64) | 供应方 |
| created_at / updated_at | datetime | 时间戳 |

无需软删除、无需版本号、无需 mock 元数据标记字段。

---

## 12. API 边界

只读接口，首版无写接口：

- `GET /api/liang/listings`——列表，支持筛选参数（品种 / 产地 / 等级 / 年份 / 价格区间 / 口径 / 交收 / 最晚可发 / 最低可用量），返回分页列表。
- `GET /api/liang/listings/{listing_id}`——详情。
- `GET /api/liang/market/summary`——概览条 + 市场发现（由固定数据集聚合）。

候选篮为前端状态，不经过后端。

---

## 13. Mock 数据真实感要求

数据 mock 但真实感足够，不让人一眼看出是假的：

- 玉米二等出厂价 2,300–2,500 元/吨、水分 14% 左右、容重 685–690 g/L、杂质 ≤1%，符合行业真实量级。
- 产地用真实地级市（绥化、榆树、铁岭、通辽…），供应方用中性虚构名（不撞真实企业）。
- 覆盖主推、备选、低价但等级不符、数量不足、字段缺失几类，为「候选对比」演示兜底。
- 固定种子幂等，重复启动不产生重复记录。

---

## 14. 空状态与异常

- 数据未初始化：列表区提示「粮源数据加载失败，请确认服务已启动」，不伪造统计。
- 筛选无结果：空列表 + 「放宽筛选条件」引导，不硬凑。
- 字段缺失：列表显示 `--`，详情明确标注「待补充」。

---

## 15. 首版范围边界

**首版完成**：

- 三栏粮源市场布局
- 概览条 + 筛选器 + 高密度列表 + 详情抽屉
- 粮小二市场发现（确定性摘要 + 点击联动筛选）
- 全局候选篮浮动气泡（加 / 减 + 跳转候选对比）
- 顶部「我要找粮」输入框（识别需求并跳转）
- 固定、幂等、真实感的 Mock 数据集
- 无网络依赖的端到端浏览演示

**首版不做**：

- 主推 / 备选 / 淘汰原因 / 待核验（归候选对比 Tab）
- 候选篮持久化、寻源任务、供应方详情（归各自 Tab）
- 完整对话流、Agent 写操作
- 公开数据接入、实时行情、刷新/同步

---

## 16. 测试与验收

- 打开 `/agent/liang` 默认展示粮源市场列表，无个性化推荐。
- 概览、列表、市场发现基于同一批固定数据，可复现。
- 价格口径清晰可辨，不同口径不混比。
- 筛选可正常过滤，清空恢复完整市场。
- 加入 / 移出候选，气泡数量实时更新，可跳转候选对比。
- 输入框识别需求后跳转候选对比。
- 页面不出现「演示数据」等字样。
- 窄屏可完成浏览、筛选、加入候选。
