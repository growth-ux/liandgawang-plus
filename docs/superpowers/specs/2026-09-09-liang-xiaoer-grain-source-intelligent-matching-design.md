# 粮小二「粮源智配」升级设计

> 日期：2026-09-09  
> 状态：产品方案稿  
> 范围：仅讨论粮小二的企业用粮画像、粮食寻源、质量适配、粮源组合与经验复用，不扩展到其他小二职责。

## 1. 设计结论

现有粮源匹配主要解决“从挂牌列表中按品种、等级、数量、预算和时间筛出候选”的问题，本质仍接近高级筛选器。它能够减少人工浏览，但尚未覆盖粮食采购中最需要专业判断的用途适配、质量价差、组合保供、证据可信度和经验复用。

粮小二应从“推荐一条粮源”升级为“生成一组可执行的粮源方案”：先理解企业买粮做什么、这家企业通常如何用粮和选粮，再形成可确认的个性化用粮标准，比较每批粮的质量与真实采购价值，必要时组合多个粮源，并说明推荐成立的依据、数据缺口及条件变化后的结果。

建议将产品定位调整为：

> **粮小二是一名懂品种、懂用途、懂质量、懂质价规则，也懂企业如何用粮和选粮，能够组合粮源并从历史采购结果中持续学习的 AI 粮源智配专家。**

## 2. 重点解决的业务痛点

不建议宣称解决粮食采购的所有问题。粮小二聚焦解决七类高频、关键痛点：

| 业务痛点 | 粮小二的解决方式 |
| --- | --- |
| 采购需求描述不专业 | 将自然语言转成可计算、可确认的专业用粮标准 |
| 不同企业使用同一套推荐逻辑 | 融合企业用粮画像和采购偏好，形成个性化寻源方案 |
| 同一等级不代表同一用途价值 | 根据品种和用途动态匹配质量指标 |
| 最低挂牌价未必最经济 | 结合质量增扣量、等级价差等形成折算粮价 |
| 单条粮源不能覆盖大批量需求 | 自动生成由一至三个粮源构成的采购组合 |
| 挂牌、质检与可供数量可信度不一 | 判断信息来源、有效期、覆盖范围和待核验项 |
| 采购经验依赖个人 | 从采用、验收、结算和供货结果中沉淀并复用企业经验 |

举例：
痛点 1：采购需求描述不专业
痛点：客户不会用规范的质量术语提需求。
例子：客户说"我要买点好一点的玉米喂猪，别太潮，别发霉，量大点便宜点"。
这句话里"好一点""别太潮""别发霉"都没法直接拿去筛粮。
粮小二把它翻译成专业标准：二等玉米、水分 ≤14%、霉变粒 ≤1%、容重 ≥685g/L、黄曲霉毒素达标。
翻译完还会让采购员确认："我理解您是要饲料用二等玉米，水分卡 14%，对吗？"

痛点 2：不同企业使用同一套推荐逻辑
痛点：同样一句"要 1000 吨玉米"，系统给饲料厂和给淀粉厂推的粮居然一模一样，这不对。
例子：
A 饲料厂：看重蛋白和霉变粒（猪吃了霉变粮会中毒），宁可贵一点也要质量稳。
B 淀粉厂：看重淀粉含量和出粉率，水分稍微高点无所谓（反正要烘干）。
面对同一批挂牌玉米，粮小二给 A 排第一的粮源，给 B 可能排第三——因为两家"用粮方式"不同，这就是文档说的"同源不同策、千企千策"。

痛点 3：同一等级不代表同一用途价值
痛点："二等"只是个笼统标签，同样叫二等的两批粮，用途价值可能差很多。
例子：两批都挂牌"二等玉米"：
甲批：容重 700、霉变粒 0.5%、蛋白 8.5% → 做饲料非常好。
乙批：容重 690、霉变粒 1.8%、蛋白 7.2% → 名义上也是"二等"，但霉变粒超标，喂猪有风险。
只看"二等"标签会误判，粮小二会根据饲料这个用途动态去看霉变粒、毒素、蛋白这些真正相关的指标，从而判断甲批更适合。

痛点 4：最低挂牌价未必最经济
痛点：便宜的那个挂牌价，算上质量扣款后可能反而更贵。
例子：
粮源 A：挂牌价 2400 元/吨，但水分 16%（超标），按规则要"扣量"——超 1% 扣 1.2%，实际结算下来吨成本变成 2450 元。
粮源 B：挂牌价 2430 元/吨，水分 13%（达标），不扣量，实际就是 2430 元。
表面上 A 便宜 30 元，实际 B 更划算。粮小二会算出这个"折算粮价"，告诉你为什么低价不一定好。

痛点 6：挂牌、质检与可供数量可信度不一
痛点：不是所有信息都一样靠谱，有的是刚出的正式质检报告，有的只是供应方口头说的一句话。
例子：
粮源 A：有 3 天前的第三方质检报告，数量经平台确认可锁定 → 高可信。
粮源 B：质检报告是两个月前的，而且只说"大概有 500 吨" → 低可信（报告过期 + 数量没核实）。
粮小二会把 B 标成"低可信"并提示"报告和数量都待核验"，不会不加说明地把 B 当成主推。


痛点 7：采购经验依赖个人
痛点：老采购员踩过的坑、积累的门道都在他自己脑子里，人一走经验就没了，新人还得重新踩一遍。
例子：
老采购员知道"丙户这家嘴上说有 500 吨，实际每次都只能交 350 吨"。
粮小二把这条经验存进企业共享记忆，下次采购时主动提示：
"参考企业近 3 次饲料玉米采购经验：丙户过去两次实际锁定量低于挂牌量，本次已按历史兑现情况降低其数量可信度。"
这样即使是新人来操作，也能自动避开老坑，经验从"个人所有"变成"企业资产"。

粮小二提供的是粮源决策支持，不能替代实物抽检、库存锁定和最终交易确认。

## 3. 职责边界

### 3.1 粮小二负责

- 识别粮食品种、用途、数量、质量底线、预算和供货要求；
- 根据不同品种与用途生成质量标准；
- 判断粮源质量、可锁定数量、报价口径和有效期；
- 依据企业或行业质价规则估算增扣量、质量调整与折算粮价；
- 生成单粮源或多粮源组合；
- 引用供应方历史供货表现和企业历史采购偏好；
- 输出推荐方案、备选方案、淘汰原因和待核验事项；
- 支持用户调整条件后重新推演。

### 3.2 粮小二不负责

- 不规划运输路线，不估算运费；
- 不输出到厂综合成本；
- 不处理融资；
- 不替代合同、主体及交易风险的独立审核；
- 不自动下单或对外承诺库存；
- 不把供应方声明包装成已经验证的事实。

## 4. 主演示场景

首期以饲料用玉米为深度样板：

> 未来 7 天需要锁定 1000 吨饲料用二等玉米，水分不超过 14%，霉变粒不超过 1%，单一供应来源不超过 70%，在保证质量稳定的前提下控制粮源采购成本。

该场景能够同时展示用途理解、动态质量标准、质价换算、多粮源组合、供应集中度控制、证据核验和企业记忆。

整体能力采用统一框架，后续可扩展到制粉小麦、压榨大豆和加工稻谷，避免项目只服务单一品种。

## 5. 核心能力设计

### 5.1 建立企业用粮画像与采购偏好画像

粮食采购中的“用户画像”不能停留在姓名、岗位或浏览记录，而应描述企业如何用粮以及采购人员如何做决策。画像分为四层：

- **企业用粮画像**：企业类型、常用品种、主要用途、周期采购量、常见批次、正式验收标准和质价规则；
- **质量偏好画像**：必须严格满足的指标、允许折价接受的指标、历史拒收和扣量原因、可接受的质量偏差；
- **寻源策略画像**：经济、质量或供应稳定偏好，是否允许多粮源组合，单一来源占比上限和常用采购批量；
- **采购人员使用画像**：偏好先看结论还是完整依据、习惯保留多少候选、经常人工确认哪些条件。

画像必须真正参与本次标准生成和方案排序，使同一批粮源面对不同企业时能够形成不同推荐，而不是只作为页面标签展示。

画像影响决策时遵循以下优先级：

> **用户本次明确条件 ＞ 企业正式采购标准 ＞ 已确认历史经验 ＞ 学习得到的偏好 ＞ 行业默认模板。**

任何画像都不能覆盖用户本次明确要求，也不能放宽食品安全和质量硬门槛。

### 5.2 从模糊表达生成专业用粮标准

粮小二先识别品种、用途、数量、质量偏好、供货期限和供应集中度，再将需求分成三类：

- **硬约束**：任何一项不满足就不能进入正式推荐；
- **可调整条件**：允许按照企业质价规则折价或扣量；
- **决策偏好**：用于在合格方案中区分经济、质量稳定和供应韧性。

系统必须区分条件来源：用户明确提出、企业正式标准、画像偏好、历史经验、行业模板建议或系统默认。AI不能将推测包装成用户要求。

只补问真正会改变匹配结果的关键问题。例如，当采购量较大时，确认是否允许多粮源组合；当用途明确但质量标准缺失时，推荐相应模板并让用户确认。

### 5.3 按品种与用途动态建标

不同粮食品种、不同加工用途不能共用一套简单指标：

- 玉米重点关注等级、水分、容重、杂质、不完善粒、霉变粒、真菌毒素，以及用途相关的蛋白或淀粉指标；
- 小麦可进一步关注蛋白、湿面筋、降落数值等加工品质指标；
- 大豆可关注完整粒率、损伤粒率、蛋白和含油率；
- 稻谷可关注出糙率、整精米率、垩白粒率等指标。

食品安全和异常气味等指标必须逐批合格，不能通过多批混合后的平均值掩盖不合格粮源。允许组合加权的质量指标，也必须依据明确的企业规则计算。

### 5.4 从挂牌价升级为质量调整后的粮源价值

粮小二不再用固定金额粗略处罚水分、杂质或容重差异，而是根据企业合同口径或行业参考规则，展示：

- 挂牌数量与预计结算数量；
- 水分、杂质等可能产生的增扣量；
- 等级和质量可能产生的扣价或溢价；
- 质量调整后的折算粮价；
- 规则来源以及结果属于正式口径还是参考估算。

这样才能解释“为什么更低的挂牌价不一定代表更好的粮源采购方案”。

### 5.5 判断粮源信息是否可信

每条关键数据都应保留来源和时效，包括质检报告、扦样时间、样品代表数量、报价有效期、挂牌数量和确认可锁定数量。

页面采用“高可信、中可信、低可信”表达，不制造无法解释的精确分数：

- 高可信：关键凭证完整且处于有效期；
- 中可信：部分字段仍需确认；
- 低可信：报告过期、范围不匹配、关键字段缺失或仅为口头声明。

低可信粮源可以作为条件候选，但必须显著提示，不能无说明地成为正式主推。


## 6. 企业共享记忆

企业画像给出相对稳定的个性化背景，企业共享记忆保存每次任务产生的具体经验。粮小二应从每次实际采购结果中学习：

- 最终采用了哪个方案及原因；
- 挂牌质检与实际验收是否存在偏差；
- 实际可锁定数量是否兑现；
- 实际结算数量和质量调整情况；
- 哪些质量指标经常触发扣量或拒收；
- 企业在同类场景中更偏好价格、质量还是供应稳定。

下一次遇到相似任务时，主动引用已确认经验：

> 参考企业近 3 次饲料玉米采购经验：该企业对霉变粒控制严于普通等级要求；某供应方过去两次实际锁定量低于挂牌量，本次已按历史兑现情况降低其数量可信度。

多次得到确认的经验可以更新企业用粮画像，例如形成“饲料玉米优先质量稳定”“单一来源通常不超过 60%”等长期偏好；单次任务结论只作为经验记录，不直接改变长期画像。

历史经验不能覆盖用户本次明确要求，不能放宽食品安全底线，也不能把单次异常直接固化成长期结论。所有记忆都要显示来源、适用原因及本次产生的影响。

## 8. AI 亮点

粮小二的 AI 价值由五部分共同构成：

1. **画像理解**：理解这家企业如何用粮、验粮和选粮；
2. **语义理解**：将模糊业务语言翻译成专业用粮标准；
3. **可信决策**：质量、安全和质价计算采用可复现规则，避免模型幻觉；
4. **组合优化**：从单条粮源排序升级为多粮源采购组合；
5. **持续学习**：实际验收和结算结果进入企业记忆并更新画像，后续任务主动引用。

核心差异化表达：

> **不是推荐一条粮源，而是生成一组满足用途、质量、数量和可信度约束的粮源方案。**

## 12. 对外表达

### 一句话版本

> 粮小二不仅懂粮，也懂这家企业如何用粮、验粮和选粮：它把一句模糊需求转化为专业用粮标准，从数百条粮源中生成个性化的多粮源组合，并通过实际验收结果持续学习。

### 汇报版本

> 传统粮源匹配解决的是“数据库里有没有这条粮”，粮小二解决的是“这批粮是否适合这家企业使用、质量差异最终值多少钱、单一粮源不足时应该怎样组合，以及过去踩过的坑这次能否自动避免”。系统融合企业用粮画像、采购人员偏好、大模型需求理解、可复现的粮食质量规则、多粮源组合决策和企业共享记忆，实现同源不同策、千企千策，让原本依赖采购人员个人经验的粮源判断变得可解释、可复用、可持续进化。
