# 粮掌柜采购协作驾驶舱：竞赛版设计

## 1. 产品主线

让用户始终知道：我在买什么粮、办到哪一步、AI 帮我解决了什么、现在需要我确认什么。

一笔采购任务贯穿始终。以原有粮掌柜协作驾驶舱为主视觉，嵌入七阶段买粮流程；节点、连线、专业结果与操作面板共享同一份采购状态。原有各小二专业页继续支持独立使用。保留深蓝底、数据青、粮达橙的视觉语言。

## 2. 七个阶段承载完整流程

| 页面阶段 | 原始流程 | 页面内容 | 用户动作 | 小二协作 |
| --- | --- | --- | --- | --- |
| 需求确认 | 买粮意图 / F2 | 确认品种/数量/到货地/交期/预算/库存可用天数、商城采购线路 | 确认需求后进入行情 | 粮掌柜整理并确认需求 |
| 行情研判 | F1 | 基于已确认需求展示相关区域报价、近期趋势、采购时机与到货建议 | 按建议采购 / 返回调整计划 / 暂时观望 | 瞻小二研判，粮掌柜汇总建议 |
| 交易准入 | F3 | 注册入驻、企业资质、风险预警、资金账户、保证金逐项核验 | 缺失时补材料并重试 | 安小二与钱小二并行 |
| 选粮点价 | F4 | 区域粮源、历史成交参考、单价/质量/库存对比、推荐理由 | 选择粮源，确认数量与价格 | 粮小二推荐，瞻小二辅助判断 |
| 提货安排 | F6a / F6b | 自提：车辆/库区时间/天气/错峰；配送：公路与多式联运价格、时效对比 | 选择自提或配送并确认方案 | 运小二与瞻小二协作 |
| 下单履约 | F7 | 订单金额、合同关键项、资金安全检查、订单与收货进度 | 核验后确认下单，履约后确认收货 | 下单前安小二/钱小二/算小二核验；下单后运小二跟踪 |
| 复盘沉淀 | F8 / F9 | 采购与物流成本拆解、参考方案比较、经营建议、经验条目 | 查看复盘，下一笔采购复用经验 | 算小二复盘，粮掌柜归档至知识大脑共享 |

登录属于入口状态，不占用采购阶段。F3 的多项核验在同屏并行展示；F6a 与 F6b 是一个阶段下的两个分支。下单不等于收货完成，收货后才能进入交易复盘。

```text

① 需求确认 ─ ② 行情研判 ─ ③ 交易准入 ─ ④ 选粮点价 ─ ⑤ 提货安排 ─ ⑥ 下单履约 ─ ⑦ 复盘沉淀

┌ 当前待办：选择粮源并点价 ───────────────────── [找粮小二办理] ┐
│                    数字人协作驾驶舱                          │
│           瞻小二                    粮小二                   │
│                     粮掌柜                                  │
│     安小二                                      运小二       │
│             钱小二                  算小二                   │
│       点击本步参与的数字人，打开右侧办理抽屉                  │
└─────────────────────────────────────────────────────────────┘

右侧抽屉（默认约半屏，可加宽）
┌ 粮小二 / 选粮点价 ─────────── [展开面板] [收起] ┐
│ 粮掌柜 · 统筹    粮小二 · 已完成    瞻小二 · 已完成 │
│ 本步办理状态                           专业依据 │
├────────────────────────────────────────────────┤
│ 本阶段完整业务内容：粮源比较、选择与价格确认     │
│ 已选粮源                     [确认并继续下一步] │
│ ▸ 采购建议、账单与企业经验                     │
└────────────────────────────────────────────────┘
```

- 默认只展示采购摘要、阶段导航、当前待办和七人协作场景，下方不再铺设表单、账单或专业结果。
- 粮掌柜始终可点击进入当前步骤。本步参与的小二同时提供可点击的形象和动作提示；待命小二保留在场景中，但不带入前序结果。
- 每个阶段只有一个办理面板。交易准入的资质、资金在同一抽屉处理；点击安小二或钱小二均进入该面板，不拆分确认操作。抽屉头部可切换本步参与者，并查看各自专业依据。
- 桌面端抽屉默认 780px、支持加宽；窄屏占满屏幕。顶部始终展示当前阶段与参与者状态，桌面确认操作吸附在内容区底部，辅助建议、账单和经验按需展开。
- 关闭抽屉不销毁当前表单草稿，也不打断正在进行的核验。完成确认后抽屉直接进入下一阶段，更新负责小二并回到内容起点；历史阶段保持只读。
- 驾驶舱复用 `SpatialAgentStage`、`AgentPod`、`AgentFlowSvg`。业务和节点状态仍来自当前采购记录，未增加流程引擎或后端接口。
- 核验开始时安小二、钱小二同时办理；缺材料或资金不足时对应节点出现异议。补件重跑后节点恢复通过。
- 改变粮源和运输，自动更新运小二、算小二的依据和金额，并清除旧交易核验结果。
- 下单、发运、到货、收货与经验沉淀持续驱动同一驾驶舱；已完成步骤可以只读回看。

## 4. 必须能演示的分支

- **正常买粮**：确认需求 → 行情研判并确认采购安排 → 核验通过 → 选粮 → 配送 → 核验下单 → 收货 → 复盘与经验沉淀。
- **资料不全**：资质检查发现缺失 → 明确缺少什么 → 补充 → 重新核验 → 恢复原任务。
- **自提**：选择自提 → 查看推荐车型、车次、库区时间与天气提示 → 确认安排。
- **风险拦截**：收款主体或合同信息不一致 → 禁用下单 → 修正信息后重新核验。
- **经验回用**：完成采购后产生有来源、有适用条件的经验；下一笔相同区域/品种的任务主动引用。

## 5. AI 亮点与证据

1. 从自然语言中整理采购条件，用户只需修正和确认。
2. 按阶段协调专业小二，将资质与资金等独立检查同时展开。
3. 推荐粮源时展示质量、交期、成本的依据，不只输出一句“推荐”。
4. 比较自提与配送的到厂总成本，展示多式联运的价格和时效取舍。
5. 异常明确定位到具体核验项，并给出修复动作。
6. 采购结束自动提炼可复用经验，后续引用显示来源任务与适用条件。

## 6. 竞赛版实现边界

第一版只实现页面与可交互的状态流转，使用统一场景数据；不新增真实认证、签约、支付或物流系统。订单、核验、运输等结果用前端状态承载，页面不显示开发术语。

沿用 React 和现有样式。原有 FastAPI、MySQL、LangChain、mem0 架构不变，不引入通用流程引擎。后续接真实服务时，把阶段动作替换为接口调用即可。

金额使用同一套数量、单价和运费计算。复盘必须标明比较基准，区分预计节约与实际结果；知识条目写清来源及适用范围，不能把一次交易直接推广为普遍结论。

现有后端任务的 completed 表示方案分派完成，不能直接视作订单履约完成。旧的任务分析记录与采购履约状态应各自准确表达。

## 7. 本次落地说明

- 入口：`/agent/da` 默认进入采购协作驾驶舱；页面不再展示「综合方案分析」独立入口；原有分析路径与旧的 `?mission=` 链接保留兼容。原方案确认后提供「继续办理采购」，携带原任务编号与专业结果接续。
- 页面版先提供山东潍坊、二等玉米/小麦的区域场景。超出支持范围的品种、地区或等级在需求整理时明确提示；不把固定运费套用到全国。
- 当前采购、核验、运输、收货与经验均为前端场景状态，不调用真实签约、付款和物流接口；自然语言使用现有规则解析。登录与 IP 识别不在本次新增范围内。
- 采购记录保存在当前浏览器 localStorage，刷新或从其他小二返回后可恢复。原有后端分析任务继续采用已有接口。
- 收货时自动生成采购经验，在企业知识大脑的「采购履约经验」区域展示；下一笔同品种、同区域采购会主动引用。此处为页面级经验闭环，尚未同步到 MySQL/mem0，也未接入各独立小二的后端检索。
- 选粮与运输可在下单前调整；历史步骤只读，下单后不能通过回看改写已确认条件。点价金额、运费、订单与复盘使用同一计算函数。

## 8. 原后端方案接续

原任务完成方案确认后，点击「继续办理采购」：

1. 保留原任务编号，并按用户实际确认的 A/B 方案读取供应商、粮源单、价格与库存。
2. 带入目标数量、地区、交期和预算，以及运小二的批次时效与加权运价。
3. 保留算小二综合成本与采购、运输之间的费用差额，以装卸、损耗等原方案费用展示；不使用区域默认报价覆盖原结果。
4. 同一任务再次接续时恢复已有采购进度，不重复创建。
5. 待风险核验、已过期交期、不支持的品种等级、缺失专业结果或批次数量不一致时明确阻止接续并解释原因。

当前完成的是后端分析结果到前端采购驾驶舱的接续，以及采购内部状态、图形、操作和经验的联动；后续交易操作仍按竞赛页面版在浏览器保存，未新增真实签约支付、物流接口，也未把履约状态反写到原后端分析任务。

### 新增验证

DOM 交互验证覆盖核验时双节点同时运行、安小二异常/恢复、方案金额与算小二节点联动、节点详情、全景收起展开、采购进度回看与恢复，以及原任务编号/实际所选方案/供应商/运价/附加成本传递。真实浏览器截图仍受当前 Chrome 启动环境限制，需打开页面复核视觉效果。

## 9. 先确认需求，再确认行情决策

- 第一阶段确认粮种、数量、收货地、交期、预算和库存天数；粮掌柜整理条件，用户确认后创建采购任务并进入行情。
- 第二阶段以已确认需求为依据，展示分析范围、报价参考与建议。当前区域现货入口支持潍坊，比较山东港口与本地库点；未新增全国区域匹配能力。
- **按建议采购**：保存研判快照与用户决定，采用建议交期，进入交易准入。
- **调整采购计划**：返回需求确认，保留同一任务。重新确认后清除旧研判，按新条件重新给出建议，需再次确认后才能进入准入。
- **暂时观望**：保存研判，停在第二阶段，尚未启动交易核验；刷新后可在同一任务继续。
- 行情面板的采购条件只读，调整统一回到第一步；历史阶段只读。
- 阶段版本升为 3。旧七步版前两步尚未办完的记录返回需求确认，保留原记录和研判供参考；交易准入及之后的进度不变。六步旧版仍兼容迁移，不补记未发生的行情确认。
- 行情使用现有竞赛参考数据与建议规则，不新增行情服务或真实交易。

验证覆盖：需求先行与条件校验、禁止跳过步骤、条件传递、观望恢复、调整后重新研判、建议交期传入交易准入、历史只读、旧记录一次性迁移，以及完整采购和原方案接续回归。

## 10. 驾驶舱分工与当前步骤一致

粮掌柜始终主理采购。需求确认由粮掌柜承接，中心只展示需求确认状态，具体采购条件在表单与任务摘要中展示，六位小二待命。行情阶段仅瞻小二参与；交易准入由安小二、钱小二核验；选粮点价由粮小二与瞻小二协作。配送阶段运小二、算小二参与，自提时加入瞻小二。下单前展示合同、资金及成本核验，下单后切换到运小二履约跟进。复盘阶段算小二提供成本与经验，粮掌柜归档供后续共享。

待命节点不带入前序结果、不提供当前专业结果入口；已完成阶段可通过流程导航回看。原综合分析驾驶舱保持原有交互。

## 11. 下单操作与核验状态

下单阶段先展示“核验交易”和核验说明，核验通过后才出现“确认下单”。核验失败直接列出阻塞原因并提供“重新核验交易”；修改收款主体后需要重新核验。核验结果和失败原因随采购记录保存，刷新后仍可继续。此处沿用页面采购流程，不新增真实交易接口。

## 12. 自然语言整理后确认条件

新建采购先输入自然语言，示例仅作为输入框提示，不预填一笔采购。点击“整理采购需求”后显示确认表单，填入识别出的粮种、数量、到货地、交期、预算和库存天数；未提及的条件留空待补。库存天数与交期分别提取。修改自然语言后需重新整理，防止按旧字段确认。表单草稿在确认前不写入已有采购记录；调整计划或沿用需求时可核对已有条件。当前仍使用确定性提取规则，区域范围保持潍坊玉米/小麦采购。

## 14. 数字人办理抽屉验证

浏览器验证覆盖：点击粮掌柜与专业小二打开抽屉、关闭后隐藏全部业务内容、草稿保留、协作成员共用业务面板、并行核验与异常补件、关闭抽屉后继续核验、专业依据、粮源比较、自提协作、面板加宽、核验下单、履约收货、经验沉淀，以及历史回看只读与返回当前阶段。桌面场景按可用宽度放大，使用自然页面滚动，不按首屏剩余高度缩小核心内容；人物、名称与办理入口随舞台同比放大。
