① 获取并保存

数据源适配器拉取最新内容，标准化品种、地区、口径、单位和时间。

② 代码计算事实

涨跌幅、价差、区间、阈值是否触发都由后端确定性计算，不交给模型猜。

③ 组织证据包

把用户采购条件、事实指标和事件按 ID 提供给模型，禁止使用包外价格。

④ 模型返回 JSON

方向、周期、置信度、行动批次、触发条件、正反依据和失效条件固定结构输出。

⑤ 校验并展示

FastAPI 校验字段、数值与证据引用；不合格则重试一次，再失败使用规则化降级结果。

首版做什么，以及明确不做什么

范围围绕“玉米行情 → 200 吨采购研判 → 关注 / 交给粮小二”这一条演示路径。

必须做完整

  • 玉米真实公开价格序列与来源时间
  • 市场全景和玉米品种行情
  • 结构化采购研判与重新研判
  • 三类关注条件与触发检查
  • 研判快照、版本和前后变化
  • 创建“交给粮小二”的预填任务

只做轻量展示

  • 小麦、稻谷、大豆有行情卡和基础走势
  • 非玉米品种可关注、可提问
  • 数据更新后台单进程调度
  • 产品内提醒同步“我的办事”
  • 模型供应商通过环境配置切换

本轮不做

  • 真实下单、合同与支付
  • 短信、电话、邮件提醒
  • 多企业、多账号与权限体系
  • 复杂粮价地图、资讯瀑布流
  • 高可用队列、分布式采集
  • 模型自行联网搜索或编造缺失数据

异常与降级

行情页面和 AI 研判解耦：即使模型失败，用户仍然能够查看事实数据。

外部数据源失败沿用最后一次成功数据，显示“数据截至……”；过期严重时降低置信度，不输出强行动建议。
部分指标缺失隐藏不能比较的序列，明确缺少哪项数据；不使用模拟值静默补齐公开数据。
模型超时或格式错误保留用户输入和事实图表，自动重试一次；仍失败则展示基于确定性指标的简版结果并允许重试。
关注条件无法检查状态改为“数据待更新”，不误报为未触发；数据恢复后重新计算。

验证方式

后端单元测试

  • 涨跌、价差和触发条件计算
  • 数据新鲜度分级
  • 事实 / 推断 / 模拟标签
  • 模型 JSON 校验与降级

接口与页面测试

  • 公开 + 模拟混合数据返回
  • Tab、筛选和图表同步
  • 加载、空数据、过期和失败状态
  • 旧研判快照不被新数据覆盖

  • 创建价格关注并模拟触发
